# Безопасность MyVibeHTML

## Модель доверия

Доступ к MyVibeHTML равносилен доступу к коду сайта. Пользователь, прошедший авторизацию и имеющий разрешённые расширения, может изменять HTML и другие разрешённые файлы. Не публикуйте редактор без HTTPS, сильного пароля и ограничения доступа на уровне web-сервера.

## Runtime и резервные копии

- `conf.ini`, lock-файлы, журнал и backup хранятся в `.myvibehtml-<hash>` рядом с document root и не должны быть доступны по HTTP;
- Nginx/Apache правила из проекта — второй уровень защиты, а не замена правам файловой системы;
- recovery использует staged/rollback путь и удаляет backup только после успешного применения.

## Авторизация и запросы

- пароль хранится через `password_hash()` и проверяется `password_verify()`;
- старый SHA-1 формат используется только для одноразовой миграции после успешного входа;
- session/CSRF tokens создаются криптографически стойкими источниками, сравнение — `hash_equals()`;
- production должен работать по HTTPS.

## Редактируемые скрипты

Скрипты сайта отключены по умолчанию. При включении они выполняются в same-origin iframe и потенциально могут обращаться к родительскому окну и активной сессии. Включайте режим только для полностью доверенного сайта и временно.

Сообщения об уязвимости не отправляйте через issue с секретами или рабочими URL. Передайте минимальное воспроизведение владельцу репозитория приватным каналом.
