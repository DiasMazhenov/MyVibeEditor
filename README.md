# MyVibeHTML

MyVibeHTML — локальный визуальный редактор HTML-страниц. Он работает внутри сайта на PHP, открывает выбранный файл в iframe, позволяет менять текст и структуру блоков, а исходный код редактировать в отдельной вкладке.

Текущая версия: **0.78**.

## Возможности

- визуальное редактирование страницы в iframe;
- вкладки `visual` и `html` без перехода на страницу авторизации;
- контекстное меню по правой кнопке мыши;
- выделение элемента, секции и блока;
- CSS-инспектор выделенного узла: live-применение разрешённых свойств, сброс и сохранение в HTML;
- дизайн-токены: просмотр и редактирование CSS custom properties через CSS-инспектор с записью в `:root`;
- навигация по внутренним ссылкам текущей страницы с безопасным открытием страниц в новой вкладке;
- отдельная защищённая админ-страница `?admin=1`: обзор проекта, счётчики, поиск файлов, настройки политики и health-проверки;
- HTML/CSS/ARIA-инспектор: текущие `tag`, `id`, `class`, `role`, ARIA-атрибуты и CSS-значения выбранного узла;
- CSS-инспектор адаптивно раскладывает все поля внутри закреплённой панели справа на desktop и bottom-sheet на мобильных без выезда за границы экрана;
- ширина desktop-панели изменяется перетаскиванием левой границы или клавишами, а при смене выделенного элемента поля перечитываются для нового узла;
- весь контент окна CSS-инспектора прокручивается одним общим scrollbar, включая HTML/ARIA и footer;
- fieldset больше не сжимается flex-контейнером и сохраняет естественную высоту всех строк;
- на desktop CSS-инспектор открывается справа на всю высоту, его левую границу можно перетаскивать для изменения ширины; на мобильных сохраняется bottom-sheet;
- операции с выделенным блоком: копирование, перемещение вверх/вниз, удаление и работа с атрибутами;
- файловый менеджер с переходом по каталогам, размером, датой изменения, загрузкой, удалением и точками восстановления;
- файловый менеджер с созданием файлов/папок, переименованием и поиском по проекту;
- поиск по содержимому проекта с ограниченными по размеру текстовыми файлами, номером строки и безопасным read-only предпросмотром совпадений;
- безопасная замена найденного текста: snapshot-проверка, построчный diff, атомарное применение и откат последней замены;
- инспектор HTML/CSS/ARIA с безопасным переименованием тегов и структурными действиями «добавить внутрь/рядом»;
- история исходника с Undo/Redo, локальными черновиками и индикатором несохранённых изменений;
- «История изменений»: постоянные снимки visual/text-редактора с восстановлением через Undo;
- настройки авторизации, визуального редактора, исходного кода, файлового менеджера и системы;
- кнопка-глаз для открытия страницы напрямую, без панели редактора;
- адаптивная панель с бургер-меню на маленьких экранах;
- адаптивный preview с режимами `Десктоп`, `Планшет` и `Телефон`;
- Responsive Preview Studio с едиными кнопками desktop/tablet/mobile и точной шириной viewport;
- локальная библиотека переиспользуемых компонентов с режимом связанной вставки и медиаменеджер изображений;
- проверка страницы и построчный diff перед каждым сохранением с явным подтверждением;
- Page Health с локальными SEO, структурными и ресурсными проверками;
- command palette по Ctrl/Cmd+K с поиском, стрелочной навигацией и Enter;
- контекстное меню с Escape, стрелочной навигацией, Home/End и возвратом фокуса;
- локальные SVG-иконки без runtime-запросов к внешним доменам;
- модульные runtime-контракты для PHP, source-map, UI contracts и transport;
- общий UI-контракт показывает видимый статус при недоступном `localStorage`/`sessionStorage` и удерживает фокус внутри открытых модальных окон с возвратом на инициатор;
- защитные HTTP-заголовки, поэтапный CSP enforcement с безопасным сбором отчётов, проверки путей и атомарная запись файлов.

CI запускает PHP/JS syntax checks, unit/security/HTTP regression и optional authenticated HTTP E2E. Пароли и cookies для E2E берутся только из GitHub Actions secrets `MYVIBEHTML_E2E_URL` и `MYVIBEHTML_E2E_COOKIE`; без них проверка явно пропускается. Для save/reload smoke можно дополнительно передать `MYVIBEHTML_E2E_SAVE_CONTENT_B64` и `MYVIBEHTML_E2E_SAVE_EXPECT`; обязательный режим включается `MYVIBEHTML_E2E_REQUIRE=1`. Полный ручной acceptance-сценарий для встроенного браузера находится в [`docs/browser-acceptance.md`](docs/browser-acceptance.md).

## Требования

- PHP 7.4+ — минимальная версия; проект проверен на PHP 8.5;
- Apache с `mod_rewrite` или Nginx с PHP-FPM;
- доступ PHP к записи runtime-каталога и конфигурации;
- JavaScript и cookies в браузере.

В проекте нет `composer.json`, `package.json` и runtime-загрузки npm/Composer-библиотек. Иконки заранее сохранены локально. Их источники и лицензия указаны в [`myvibehtml-icons/README.md`](myvibehtml-icons/README.md).

## Установка на Apache

Подробный production-чеклист для Apache, Nginx/PHP-FPM, локального запуска, прав и диагностики находится в [`docs/deployment.md`](docs/deployment.md).

1. Скопируйте каталог `myvibe` внутрь document root сайта. Например:

   ```text
   /var/www/example/myvibe/
   ```

2. Разместите `myvibehtml.php`, JavaScript-модули (`myvibehtml.js`, `myvibehtml-source-map.js`, `myvibehtml-ui-contracts.js`, `myvibehtml-transport.js`, `myvibehtml-shell-controls.js`, `myvibehtml-admin.js`), CSS (`myvibehtml-admin.css` и editor CSS), `myvibehtml-icons/` и `lang.ini` в одном каталоге.

3. Скопируйте `.htaccess` из проекта в каталог редактора или в document root — в зависимости от того, какой URL должен вести на `myvibehtml.php`.

4. Убедитесь, что PHP может создать runtime-каталог вида `.myvibehtml-<hash>` рядом с document root. Конфигурация и блокировки не должны быть доступны из браузера.

5. Откройте URL редактора, например:

   ```text
   https://example.test/myvibehtml.php?q=index.html
   ```

6. После первого входа сразу задайте собственный пароль в настройках. Пароль в репозитории не хранится.

Пароль хранится через `password_hash()` и проверяется `password_verify()`. Старый SHA-1-хеш принимается только один раз для миграции после успешного входа. Серверная сессия имеет TTL и очищается после истечения. Для production редактор принимает HTTPS; если TLS завершается на доверенном reverse proxy, задайте `MYVIBEHTML_TRUST_PROXY=1` и передавайте `X-Forwarded-Proto: https`.

## Установка на Nginx

Используйте [`nginx.conf.example`](nginx.conf.example) как основу для server block. В конфигурации обязательно должны присутствовать:

- `try_files` с fallback на `myvibehtml.php`;
- `SCRIPT_FILENAME` для PHP-FPM;
- запрет dotfiles, `backup/`, `*.ini` и `*.log`;
- ограничение размера загрузки через `client_max_body_size`;
- HTTPS для production.
- PHP-редактирование отключено по умолчанию; включайте его только явным `allow_php=1` для доверенного администратора.

Путь к сокету PHP-FPM (`fastcgi_pass`) замените на путь вашей системы. Перед reload проверьте конфигурацию командой `nginx -t`.

## Локальный запуск

Для тестового сайта с document root `/path/to/site`:

```bash
php -S 127.0.0.1:8080 -t /path/to/site /path/to/site/myvibe/dev-router.php
```

Если `myvibe` лежит внутри document root, передавайте router из фактического document root. Нельзя запускать PHP-сервер с корнем самого каталога плагина, если конфигурация сайта рассчитана на родительский document root: это приводит к несовпадению путей и ошибке `Проблема с DOCUMENT_ROOT`.

## Авторизация и DOCUMENT_ROOT

Надпись `Проблема с DOCUMENT_ROOT` в форме означает, что сервер не смог корректно определить или записать конфигурацию сайта. Проверьте:

1. `DOCUMENT_ROOT` указывает на реальный document root сайта;
2. файл `conf.ini` доступен PHP на запись;
3. runtime-каталог `.myvibehtml-<hash>` создаётся рядом с document root;
4. URL редактора не смешивает document root сайта и отдельный корень каталога плагина;
5. при Nginx корректно настроен `SCRIPT_FILENAME`.

После нескольких неверных попыток вход временно блокируется согласно настройкам. В production не очищайте конфигурацию вручную без резервной копии.

## Работа в редакторе

### Визуальный режим

Вкладка `html` показывает страницу в iframe. Нажатие на объект выделяет его, а правая кнопка открывает контекстное меню. В меню доступны уровни `main`, `section`, `div` и текущий текстовый элемент. Нижняя панель содержит действия над выбранным блоком.

### HTML/CSS/ARIA-инспектор

Выделите элемент, нажмите правую кнопку мыши и выберите `Изменить CSS` или `HTML / ARIA`. Инспектор показывает текущие значения выбранного узла: `tag`, `id`, `class`, `role`, `aria-label`, `aria-hidden`, `title`, а также вычисленные и inline-значения 13 разрешённых CSS-свойств. Изменения применяются сразу в iframe и синхронно отражаются в исходном HTML через source map. На desktop инспектор закреплён справа на всю высоту и изменяет ширину через левую границу, на mobile открывается нижней прокручиваемой панелью.

### Исходный код

Вкладка `text` открывает код текущего файла. Переключение выполняется AJAX-запросом и сохраняет текущую авторизованную сессию. Кнопка `Сохранить` появляется в панели после изменения содержимого.

### Просмотр сайта

Кнопка с глазом открывает `site_preview_url` в новой вкладке. Это прямой URL HTML-файла, поэтому в адресе нет `?q=...` и панели редактора.

В визуальном режиме переключатель размера preview меняет ширину iframe на полный desktop, `768px` планшета или `390px` телефона. Высота и содержимое остаются рабочими, поэтому responsive CSS страницы можно проверять в редакторе без изменения файла.

### Компоненты и медиа

Кнопка компонентов открывает локальную библиотеку в браузере. В контекстном меню выбранного узла доступно `Сохранить компонент`; сохранённый компонент можно вставить после текущего выделения, вставить кнопкой `Связать`, обновить текущим выделением или удалить. Связанная вставка получает безопасный маркер `data-myvibe-component-id`: при изменении записи открытые редакторы на том же origin получают обновление через `storage` event и создают локальный draft. Сервер автоматически не перезаписывается — каждую изменённую страницу нужно явно сохранить, поэтому изменения не теряются из-за фоновой синхронизации. Старые записи библиотеки автоматически получают совместимый id при чтении. Кнопка `Медиа` в файловом менеджере показывает найденные изображения (`avif`, `gif`, `ico`, `jpg`, `jpeg`, `png`, `svg`, `webp`) и открывает их прямой URL.

История изменений доступна в текстовом режиме через кнопку `История изменений`. Она хранит до 40 последних снимков текущего файла в localStorage браузера; снимки visual и text режимов используют общий ключ проекта и не отправляются на сервер.

### Файлы

Файловый менеджер показывает только безопасные пути внутри настроенного корня. Скрытые служебные файлы, `conf.ini`, журналы и каталог backup блокируются на уровне приложения и веб-сервера.

### Настройки

Разделы настроек раскрываются по клику на заголовок. Изменения применяются кнопкой `Сохранить`; пароль и параметры сессии меняйте только через авторизованную панель.

### Дизайн-токены

В CSS-инспекторе выбранного элемента блок `Дизайн-токены` находит CSS-переменные из исходника, показывает их текущие значения и позволяет создать новую переменную. Кнопка `Применить` обновляет `:root`, live-preview и исходный HTML; опасные конструкции, `url()`, скриптовые выражения и слишком длинные значения отклоняются.

### Навигация и Responsive Preview Studio

Кнопка навигации использует отдельную иконку карты страниц, сканирует внутренние ссылки текущей страницы в iframe и показывает их в компактном списке; ссылки открываются в новой вкладке без внешних запросов редактора. В Responsive Preview Studio оставлены единые быстрые кнопки desktop, tablet и mobile — без дублирующего выпадающего списка. Выбор меняет ширину iframe без перезагрузки, запоминается для текущего файла и не меняет исходный HTML.

### Page Health

Проверка перед сохранением дополнительно ищет отсутствие `lang`, пустой/отсутствующий `title`, `meta description`, `meta viewport`, неверное количество `h1`, ссылки без `href` и чрезмерно тяжёлую страницу по числу ресурсов/строк. В диалоге показывается локальная оценка `0–100`; страница и код никуда не отправляются.

| `applyMarkupProperty()` / `syncMarkupSource()` | Меняют allowlist HTML/ARIA-атрибутов в iframe и обновляют соответствующий opening tag в исходнике. |
| `replaceStructuralTag()` / `insertStructuralNode()` | Переименовывают разрешённый HTML-тег и вставляют новый текстовый элемент через безопасную allowlist и source-map синхронизацию. |
| `sourceHistoryUndo()` / `sourceHistoryRedo()` | Управляют историей исходного редактора и обновляют dirty-состояние. |
| обработчик вкладок | Переключает визуальный и исходный режимы с сохранением сессии. |
| обработчик preview | Переключает ширину визуального iframe между desktop/tablet/mobile и открывает прямой URL сайта в новой вкладке. |
| обработчик context menu | Показывает уровни DOM и действия над выбранным элементом. |
| обработчик mobile menu | Открывает бургер и направляет пункты меню к соответствующим контролам панели. |

| `myvibehtml-transport.js` | Изолированный transport-контракт: cookies, совместимый SHA-1/Base64, URL-safe Base64, AJAX и генератор токенов через `myvibehtml-ui-contracts.js`. |

## Безопасность

- внешнее обновление и удалённые endpoints отключены;
- `conf.ini`, backup, dotfiles, `*.ini` и `*.log` закрыты в Apache/Nginx/router;
- symlink не принимаются как конфигурация, исходный файл или backup-цель;
- конфигурация, HTML и резервные копии сохраняются атомарно, а backup хранится в runtime-каталоге вне document root;
- конфигурационный lock удерживается на всём цикле чтения/изменения/записи, поэтому параллельные запросы не теряют обновления; recovery сначала staging/rollback, затем commit;
- сессии и CSRF-токены создаются криптографически стойкими случайными значениями, сравнение выполняется через `hash_equals()`;
- задаются `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, `Cache-Control` и `X-Permitted-Cross-Domain-Policies`;
- CSP принудительно применяется на auth/source/error-поверхностях; visual preview по умолчанию остаётся Report-Only, потому что редактируемая страница может содержать собственные inline-скрипты и стили. Для совместимого тестирования visual enforcement можно явно включить `MYVIBEHTML_CSP_VISUAL_ENFORCE=1`; скрипты сайта в редакторе отключены по умолчанию и при включении требуют доверия к same-origin коду.
- CSP-нарушения принимаются локальным `POST ?csp-report=1`; в лог попадают только ограниченные поля отчёта, без raw payload.
- статусные сообщения панели и файлового менеджера выводятся через `textContent`; `innerHTML` оставлен только в штатном source/visual HTML-потоке редактора;
- ответ списка файлов разбирается через `DOMParser` и allowlist тегов/атрибутов до вставки в DOM.

Проверка проекта:

```bash
sh security-smoke.sh
MYVIBEHTML_BASE_URL=http://127.0.0.1:8080 sh tests/regression.sh
php -l myvibehtml.php
php -l dev-router.php
node --check myvibehtml.js
node --check myvibehtml-transport.js
git diff --check
```

## Известные ограничения

- проект рассчитан на один сайт и локальное администрирование, а не на многопользовательскую CMS;
- visual preview остаётся Report-Only без `MYVIBEHTML_CSP_VISUAL_ENFORCE=1`; после включения enforcement inline-скрипты/стили сайта могут блокироваться и требуют отдельной проверки совместимости;
- реальный production acceptance зависит от прав PHP-FPM, Apache/Nginx rewrite и структуры document root.

## Внешние источники и библиотеки

Runtime-библиотеки отсутствуют. Единственные внешние источники относятся к заранее скачанным SVG-иконкам Tabler через Iconify; ссылки и MIT-лицензия перечислены в [`myvibehtml-icons/README.md`](myvibehtml-icons/README.md). При работе редактора запросы к Iconify, Flaticon и `textolite.ru` не выполняются.
